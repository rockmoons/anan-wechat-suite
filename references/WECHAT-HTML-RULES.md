# 公众号 HTML 硬经验（踩过的坑）

> 这份文件是本技能排版引擎（`scripts/typeset.py`）的设计依据。
> 每一条都是**公众号编辑器真实行为**，不是理论推测。改引擎前先读这里。

---

## 一、四条硬规矩（违反任何一条，粘过去就白排了）

### 1. 只用内联 style —— 不写 `<style>`、不用 `class`

公众号编辑器在粘贴时会做一次清洗：`<style>` 标签整段丢弃，`class` 属性剥掉，
`id` 也不保留。**只留下元素上的内联 `style=""`。**

后果：任何依赖外部 CSS 的排版（包括大部分 Markdown 渲染器出的 HTML）粘过去都会变成纯文本样式。

本引擎的做法：所有样式在生成时就写死在每个元素上。

### 2. 需要背景色 / 边框的块，用 `<section style="...">` 包一层

直接给 `<p>` 或 `<blockquote>` 加 `background-color`，
在部分场景（尤其是块内有嵌套元素、或跨段粘贴时）会被吃掉，表现为背景只覆盖了半行或干脆没有。

稳的写法是外面套一个 `section`，把背景和边框放在 `section` 上，里面放 `<p style="margin:0">`：

```html
<section style="background:#f5f8fd;border-left:3px solid #1a6dd4;padding:12px 16px;margin:16px 0;">
  <p style="margin:0;font-size:15px;color:#5a6472;line-height:1.8;">引用内容</p>
</section>
```

### 3. ★ `<li>` 里以 `<strong>` 开头，整行都会变粗

这是最容易踩、最难自查的坑。你写：

```html
<li><strong>第一步</strong>：打开插件-技能。</li>
```

公众号渲染出来是：

> **第一步：打开插件-技能。**   ← 整行都粗了

原因：公众号编辑器对列表项的样式处理会把首个强标签的字重继承到整行。

**解法**：在强标签后面用一个 `font-weight:normal` 的 `span` 把字重断开：

```html
<li style="..."><strong style="font-weight:bold;color:#14315c;">第一步</strong><span style="font-weight:normal;">：打开插件-技能。</span></li>
```

本引擎在渲染列表项时会自动检测「是否以 `<strong>` 开头」，是就自动补这个 `span`。

### 4. 表格用真正的 `<table>`

用 div + flex 拼出来的「表格」在公众号里会散架。用 `<table>` + `<thead>` + `<tbody>` + `<th>`/`<td>`，
把 `border-collapse:collapse` 和单元格边框都写成内联样式，粘过去能完整保留。

## 二、Windows 上必踩的两个文件坑

### 1. ★ BOM 会让首个标题消失

Windows 记事本、PowerShell 的 `Set-Content` / `Out-File` 默认给 UTF-8 文件加 BOM（字节 `EF BB BF`，字符 `\ufeff`）。

排版引擎逐行匹配 `^(#{1,6})\s+` 时，第一行变成 `\ufeff# 标题`，匹配不上，
于是 **H1 丢失**，首行被当成普通段落输出。标题是文章最重要的一行，丢了很扎眼。

**解法**：读文件时显式剥掉 `\ufeff`。

```python
raw = open(path, "rb").read()
had_bom = raw.startswith(b"\xef\xbb\xbf")     # 顺便告诉用户一声
text = raw.decode("utf-8-sig", errors="replace").replace("\ufeff", "")
```

本引擎除了自己剥，命令行还会打印「带 BOM 已自动剥除」，让用户知道发生了什么。

### 2. CRLF 会让 `$` 行为异常

同一份 Markdown 在 Windows 上换行是 `\r\n`。如果正则里用了 `$` 又没考虑，
行尾会多出一个 `\r`，匹配结果和你想的不一样。

**解法**：读取后统一归一。

```python
text = text.replace("\r\n", "\n").replace("\r", "\n")
```

## 三、图片：本地路径粘过去是无效的

**公众号只认它自己服务器上的图片。** 把 `<img src="images/01.png">` 粘进编辑器，
图片会全部丢失或显示为裂图。

正确的两种做法：

**A. 手动粘贴（没配密钥 / 不想配时走这条；谁都能用，永远可用 —— 但要显式加 `--mode paste`）**

1. 用**浏览器**打开排版好的完整 HTML（`--full-html` 生成的那份）
2. 在页面上全选（Ctrl+A）→ 复制（Ctrl+C）
3. 进公众号后台编辑器粘贴（Ctrl+V）

浏览器复制时会把图片数据一起放进剪贴板，公众号收到后会**自动把图片上传**到自己的素材库。
这是唯一能让本地图片「自动」进公众号的路子。

**B. 走 API 发布（服务号）**

封面图必须单独上传为**永久素材**拿 `thumb_media_id`（草稿接口的必填项）。
正文图片若要自动化，需要走公众号的图文素材接口，本技能目前**不做**正文图片的自动上传——
正文图请仍按 A 的方式粘贴，或在编辑器里手动插图。

> ⚠️ 粘完务必检查一遍图片：GIF、透明 PNG、超长图最容易出问题。

## 四、封面图的两种比例

公众号封面会被裁成两种：

| 用途 | 比例 | 说明 |
| --- | --- | --- |
| 首图大图 | 2.35 : 1 | 文章顶部 |
| 分享小图 | 1 : 1 | 转发到聊天 / 朋友圈时的缩略图 |

**主体务必居中**，两侧留出安全边距，否则裁成 1:1 时会被切掉关键内容。

## 五、字号与排版的可读性经验值

| 项 | 建议值 | 说明 |
| --- | --- | --- |
| 正文字号 | 15–16px | 手机上是主流阅读尺寸 |
| 行高 | 1.75–1.9 | 中文行高要比英文大一档 |
| 段间距 | 14–18px | 比行高大一点，段落才有呼吸感 |
| 字间距 | 0.4–0.6px | 中文加一点点字距更透气 |
| 正文两侧边距 | 由公众号控制 | 不要自己加左右 padding，会顶到边 |
| 代码字号 | 12–13px | 比正文小一档，且必须 `white-space:pre` + `overflow-x:auto` |

**正文一律 `text-align:justify` + `word-break:break-word`**，
避免中文两端参差、以及长英文单词 / URL 撑破版心。

## 六、深色主题（night）的额外注意

- 深色背景必须放在最外层的 `section` 上，且**要包住全部内容**，
  否则粘到公众号后会露出白色底。
- 深色底上的链接色要单独调亮，默认蓝在深底上对比度不够。
- 公众号本身不支持深色模式适配，深色主题对所有读者都是深色，选之前想清楚。
